# Galaxy Book — Telegram-бот бронирования

Бот показывает клиентам расписание помещений из Google Calendar, афишу
мероприятий и принимает заявки на бронь. Администратор подтверждает или
отклоняет заявки прямо в Telegram.

## Что умеет

**Клиент**
- 📅 **Забронировать**: помещение → день → свободное время начала → длительность →
  имя, телефон, кол-во человек, комментарий → заявка.
- 👀 **Занятость на день**: все помещения на выбранный день — что занято, что свободно.
- 🎭 **Афиша**: все мероприятия на 30 дней вперёд с пометкой места и кнопками
  фильтра по месту (Зал, Тапчан, Мастерская, Фортепиано).
- 📋 **Мои брони**: список своих броней и их отмена.
- ⏰ Напоминания за 24 ч и за 2 ч до начала.

**Администратор**
- Получает каждую заявку с кнопками «✅ Подтвердить / ❌ Отклонить».
- `/pending` — все заявки, ожидающие решения.
- Получает уведомление, когда клиент отменяет бронь.

## Правила бронирования

| Помещение | Минимум |
|---|---|
| 🏛 Зал | 1 час |
| 🛋 Тапчан (над баром) | 1 час |
| 🎨 Творческая мастерская | 1 час |
| 🎹 Фортепиано | 30 минут |

- Рабочие часы 09:00–22:00, бронировать можно на 30 дней вперёд.
- Время начала выбирается кнопками с шагом 30 минут (9:00, 9:30, 10:00…),
  длительность тоже кратна 30 минутам.
- **Перерыв 5 минут.** Если соседняя бронь стоит вплотную, время сдвигается
  автоматически. Пример: в мастерской заняты 16:00–17:00 и 18:00–19:00, клиент
  выбирает 17:00 на 1 час и получает **17:05–17:55**. Если соседей вплотную нет,
  бронь остаётся 17:00–18:00.
- Пока админ не подтвердил заявку, время уже занято: в календаре появляется
  событие «⏳ Имя (заявка)». После подтверждения название меняется на «Имя»,
  после отказа событие удаляется.
- **Все события видны всем с названиями** в расписании дня: и брони клиентов
  через бота (🔴), и то, что вы вносите вручную (🎭).
- **В «Афишу»** попадают только события, внесённые вручную (лекции, концерты).
  Брони клиентов через бота в афишу не попадают. Никаких значков ставить не нужно.
- Общий календарь «Galaxy Book» тоже попадает в «Афишу». Если в поле
  **«Место»** события написано название помещения (например «Зал»), это
  помещение считается занятым. Ключевые слова задаются в `config.yaml` → `aliases`.
- События, у которых в Google Calendar стоит «Показывать как: Свободен», не
  считаются занятыми.

Все эти значения меняются в `config.yaml` без правки кода.

## Установка на Windows-сервер

### Шаг 1. Python
Скачайте Python 3.11 или новее с https://www.python.org/downloads/ и при установке
отметьте **«Add python.exe to PATH»**.

Скопируйте папку проекта на сервер в `C:\bronbot` и запустите
**`install.bat`**. Он создаст окружение, установит библиотеки и файлы
`config.yaml` и `.env`.

### Шаг 2. Доступ к Google Calendar (один раз)
Бот работает с календарями от имени аккаунта **galaxybook2018@gmail.com**: вы
один раз входите в браузере, дальше бот обновляет доступ сам. Календари ни с
кем расшаривать не нужно, клиенты видят расписание только через бота.

Всё делается в https://console.cloud.google.com/ в проекте **My First Project**:

1. **APIs & Services → Library**: найдите *Google Calendar API* и нажмите **Enable**
   (если уже включено — пропустите).
2. **Google Auth Platform** (или **APIs & Services → OAuth consent screen**) →
   **Get started**:
   - App name: `Galaxy Book бот`, User support email: ваш email;
   - Audience: **External** (если есть вариант **Internal** — выберите его);
   - Contact email: ваш email → согласиться → **Create**.
3. **Audience** (Аудитория) → **Publish app** → **Confirm**.
   ⚠️ Это важно: если оставить статус «Testing», доступ будет слетать
   каждые 7 дней. Проверка приложения Google для этого **не нужна**.
4. **Clients** (или **Credentials → Create credentials → OAuth client ID**) →
   **Create client** → Application type: **Desktop app** → **Create**.
5. Нажмите **Download JSON**, переименуйте скачанный файл в
   **`credentials.json`** и положите в `C:\bronbot`.
   ⚠️ Никому не пересылайте этот файл.

### Шаг 3. Вход в Google (один раз)
Запустите **`authorize.bat`**. Откроется браузер:
1. Войдите под **galaxybook2018@gmail.com**.
2. Google напишет «Google hasn't verified this app / Приложение не проверено».
   Это нормально: приложение ваше. Нажмите **Advanced (Дополнительно)** →
   **Go to Galaxy Book бот (unsafe)**.
3. Разрешите доступ к календарю → **Continue**.

В папке появится файл `token.json`: это сохранённый доступ, его тоже никому
не передавайте. Если когда-нибудь бот напишет в `bot.log`, что доступ к Google
не обновляется (например, вы сменили пароль), просто запустите `authorize.bat`
ещё раз.

### Шаг 4. Telegram-бот
1. В Telegram откройте **@BotFather** → `/newbot`, задайте имя и получите **токен**.
2. Узнайте свой Telegram ID через бота **@userinfobot**.
3. Впишите оба значения в файл `.env`:
   ```
   BOT_TOKEN=123456789:AA...
   ADMIN_ID=123456789
   ```
4. Администратор должен **сам написать боту `/start`**, иначе Telegram не даст
   боту присылать ему заявки.

### Шаг 5. Календари и проверка
Запустите **`check.bat`**. Он выведет все ваши календари с их идентификаторами,
например:
```
  'Зал'                               id: abc123...@group.calendar.google.com
```
Скопируйте id каждого помещения в `config.yaml` (поле `calendar_id`) и
запустите `check.bat` ещё раз: напротив всех календарей должно быть ✅.

### Шаг 6. Запуск
**Проверка:** запустите `run.bat`, напишите боту `/start` и убедитесь, что всё
работает. Потом закройте окно `run.bat`.

**Работа в фоне (основной режим):** запустите **`background_on.bat`** и
подтвердите запрос Windows. Бот:
- работает без окна;
- сам запускается при включении сервера, даже если никто не вошёл в Windows;
- сам перезапускается, если упал или пропадал интернет.

Управление (каждый файл делает своё и сам закрывается; окно остаётся открытым
только при ошибке):

| Файл | Что делает |
|---|---|
| `update.bat` | **обновить бота**: скачать новую версию и перезапустить (если обновлений нет — ничего не трогает) |
| `bot_status.bat` | работает ли бот + последние строки `bot.log` |
| `bot_stop.bat` | остановить бота |
| `bot_start.bat` | запустить снова |
| `background_on.bat` | включить фоновый режим и автозапуск |
| `background_off.bat` | выключить фоновый режим и автозапуск |

Если запускать эти файлы из PowerShell, открытого «от имени администратора»,
лишних окон и запросов Windows не будет совсем.

⚠️ Не запускайте `run.bat`, пока бот работает в фоне: два бота с одним токеном
мешают друг другу.

---|---|
| `background_on.bat` | включить фоновый режим и автозапуск |
| `bot_status.bat` | работает ли бот + последние строки `bot.log` |
| `bot_stop.bat` | остановить бота (например, перед `git pull`) |
| `bot_start.bat` | запустить снова |
| `background_off.bat` | выключить фоновый режим и автозапуск |

⚠️ Не запускайте `run.bat`, пока бот работает в фоне: два бота с одним токеном
мешают друг другу.

**Обновление бота:** `bot_stop.bat` → в PowerShell `git pull` → `bot_start.bat`.

## Файлы

| Файл | Назначение |
|---|---|
| `config.yaml` | Настройки: календари, часы, шаг, перерыв, минимумы |
| `.env` | Токен бота и ID админа (секретно) |
| `credentials.json` | OAuth-клиент Google (секретно) |
| `token.json` | Сохранённый вход в Google (секретно) |
| `bookings.db` | База заявок (создаётся автоматически) |
| `bot.log` | Журнал работы, смотреть при ошибках |
| `service.ps1` | Управление фоновым режимом (используется bat-файлами) |

Код:
- `bot/slots.py`: расчёт свободного времени и правило перерыва 5 минут
- `bot/gcal.py`: работа с Google Calendar
- `bot/service.py`: заявки, подтверждение, отмена
- `bot/handlers.py`: диалоги Telegram
- `bot/reminders.py`: напоминания

## Для разработчика
```
pip install -r requirements.txt pytest
python -m pytest
```
Тесты проверяют правила слотов и полный сценарий бронирования с фейковыми
Telegram и Google Calendar.
